# Check-AI: две версии, одно исходное ядро

Этот режим **не заменяет** разработанную методику Check-AI. Все исходные правила, критерии, вкладки, схема заключения, подсветка и стилометрия сохраняются. Мы дорабатываем отдельные модули только после сравнительных испытаний, одинаково для обеих версий.

## Схема

- `src/`, `vendor/`, `build.py`, `index.html` — **сохраняются** как каноническое ядро и опубликованная исходная версия.
- `tools/build_dual.py` — на основе **тех же** исходных файлов создаёт два HTML, не переписывая `index.html`.
- `dist/offline/index.html` — весь существующий анализ и экспорт, упакованные в один HTML без запросов на Google Fonts. Работает через двойной щелчок по файлу, интернет не требуется. Анализ и DOCX не отправляются за пределы устройства.
- `dist/online/index.html` — тот же анализ, но с необязательной кнопкой «ИИ-экспертиза». Исходный отчёт не изменяется; дополнительный результат показывается отдельно.
- `online/online_addon.js` — только новая вкладка-панель; она не вмешивается в `src/analyzer.js`, `src/ui.js` и экспорт исходного заключения.
- `online/server.mjs` — автономный Node.js 22+ сервер для онлайн-панели, хранящий API-ключ исключительно на сервере.

## Как собрать и проверить

```bash
python3 tools/build_dual.py
```

Двойным щелчком откройте `dist/offline/index.html`. Старый `index.html` не изменяется.

Для дополнительной онлайн-экспертизы требуется доступ к OpenAI API (оплачивается отдельно от ChatGPT Plus), Node.js 22+, а также код доступа к вашему серверу.

macOS/Linux:

```bash
export OPENAI_API_KEY="ваш_ключ"
export CHECK_AI_ACCESS_TOKEN="длинный_случайный_секрет"
export OPENAI_MODEL="gpt-6"
node online/server.mjs
```

Windows PowerShell (только в терминале, не сохраняйте секреты в репозиторий):

```powershell
$env:OPENAI_API_KEY="ваш_ключ"
$env:CHECK_AI_ACCESS_TOKEN="длинный_случайный_секрет"
$env:OPENAI_MODEL="gpt-6"
node online/server.mjs
```

По умолчанию сервер доступен **только на своём компьютере**: http://127.0.0.1:8787 . В онлайн-панели нужно указать `CHECK_AI_ACCESS_TOKEN`. Секрет не сохраняется браузером в localStorage; поле существует только во время открытой сессии.

**Публичный онлайн-сайт** потребует отдельного размещения Node.js-сервера с HTTPS, проверкой доступа, лимитами и защитой API-ключа. GitHub Pages сам по себе поддерживает статический интерфейс, но не может безопасно выполнять серверные вызовы OpenAI API. Не вставляйте API-ключ в браузерный JavaScript или репозиторий.

## Как устроена конфиденциальность

- Сначала весь DOCX локально проверяется исходным Check-AI.
- Онлайн-панель показывает ровно те отрывки, которые предполагается отправить (не более 24 абзацев, до 1000 символов каждый). Пользователь может отказаться.
- Только после отдельного согласия и нажатия кнопки фрагменты передаются серверу, а затем в API модели. Файл целиком не пересылается.
- `store: false` в запросе к Responses API отключает хранение ответов через параметр store, но не отменяет все применимые правила хранения и обработки данных API.
- Сервер не ведёт логирование фрагментов. Обратный результат не подменяет исходную экспертизу и не подтверждает авторство текста.
- Проверяемые фрагменты могут включать персональные данные. Перед онлайн-анализом обезличивайте информацию, если документ конфиденциальный.

## Что пока не завершено

- Онлайн API нельзя реально проверить без собственного API-ключа и оплачиваемого доступа; GitHub Actions проверяет только сборку и синтаксис.
- Нужна ручная регрессия на реальных DOCX, включая таблицы, изображения, формулы и экспорт отчётов.
- Дополнительно можно предложить *локальную языковую модель* через отдельный адаптер (например, Ollama): без интернета и облачного API, но с требованиями к мощности компьютера и возможными отличиями качества.
- Необходимо обеспечить одинаковые варианты анализа и формат исходного отчёта при развитии общего ядра. Онлайн-анализ всегда маркируется дополнительным модулем.

## Развитие без ломки структуры

1. Автоматические контрольные DOCX с известными техническими следами: сначала устраняем ложные срабатывания и баги без изменения методики заключения.
2. Общие точечные улучшения `src/` одновременно попадают в офлайн и онлайн сборки.
3. Параллельно улучшаем ИИ-дополнение, сохраняя исходные выводы и объясняя расхождения.
4. Только после независимой валидации обсуждаем корректировку порогов и веса признаков.
