# Check-AI: один сайт, два режима анализа

Публичный интерфейс: https://aminkalinin-boop.github.io/Check-ai/

В **том же интерфейсе** над загрузкой документа появляется переключатель:
- **Офлайн · на устройстве** — оригинальная проверка DOCX, включая все существующие признаки, вкладки, локализацию, Word-отчёт и подсветку. Документ не покидает компьютер.
- **Онлайн · с ИИ и интернетом** — всё то же локальное ядро **плюс** необязательная отдельная ИИ-экспертиза фрагментов и библиографических записей с поиском в интернете.

Результаты исходного механизма не заменяются и не перезаписываются: онлайн-анализ выводится отдельным блоком.

## Архитектура без переписывания ядра

- `src/analyzer.js` и остальные оригинальные модули остаются основой обеих версий.
- `src/robustness.js` — дополнительный слой **справочных** проверок: автокорреляция длины предложений; сводка тире, кавычек, «ё»; процентные утверждения без ближайшего указания источника/методики.
- `online/online_addon.js` — добавляет переключатель на исходную страницу, не меняя оригинальные вкладки, процесс локального анализа или Word-отчёт.
- `online/server.mjs` — необязательный Node.js API-сервер, который отправляет согласованные фрагменты через Responses API. Модель имеет доступ к `web_search` и возвращает источники, если они доступны.
- `build.py` — собирает **публичный** `index.html` вместе с переключателем: `python3 build.py`.
- `tools/build_dual.py` — создаёт `dist/offline/index.html` (автономная копия) и `dist/online/index.html` (копия страницы с переключателем). В обоих используется одно аналитическое ядро.

Программная типографическая «зачистка» не может надёжно отличаться от обычной редакторской нормализации, поэтому в программе по этим признакам **нет автоматического обвинения**. Аналогично регулярность длины предложений и отсутствие локального указания источника возле числа — **только поводы для ручной проверки**.

## Почему онлайн-режим ещё требует сервер

GitHub Pages публикует статические файлы, не принимает серверные секреты и не может самостоятельно безопасно вызывать платный OpenAI API. Подписка ChatGPT не даёт браузерному приложению прямого доступа к текущему диалогу или «уму» этой сессии.

Код серверной интеграции подготовлен, но для полноценного автоматического режима необходимы:
1. Отдельный оплачиваемый API-проект и переменная окружения `OPENAI_API_KEY`.
2. Сервер с HTTPS, на котором запущен Node.js 22+ (секрет хранится на сервере).
3. `CHECK_AI_ACCESS_TOKEN` — длинный секрет доступа к установленному серверу.
4. `CHECK_AI_ALLOWED_ORIGIN=https://aminkalinin-boop.github.io` для браузерного доступа с GitHub Pages.
5. Ввести базовый URL этого сервера в появившемся поле онлайн-режима, либо задать `window.CHECK_AI_API_URL` в конфигурации сайта.

До настройки сервера переключатель работает, но **автоматический запрос к ИИ недоступен**. Можно воспользоваться кнопкой переноса отрывков в ChatGPT вручную; требуется отдельное подтверждение, и содержимое не отправляется автоматически.

Для местной проверки после сборки:

```bash
# Linux/macOS
OPENAI_API_KEY=... CHECK_AI_ACCESS_TOKEN=... node online/server.mjs
```

Windows PowerShell:

```powershell
$env:OPENAI_API_KEY="..."
$env:CHECK_AI_ACCESS_TOKEN="..."
node online/server.mjs
```

По умолчанию локальный сервер слушает только `127.0.0.1:8787`; для публичного хостинга требуется явная сетевая конфигурация, HTTPS и ограничение доступа.

## Конфиденциальность и ограничения

Исходный DOCX никогда автоматически не отправляется в онлайн API. Приложение показывает предлагаемые к отправке данные: до 24 текстовых абзацев по 1000 символов и до 16 библиографических записей по 500 символов. Запрос выполняется **только после согласия**. Доступный в браузере пароль доступа не сохраняется через localStorage. API-ключ модели никогда не вводится в браузер и не публикуется в GitHub.

Онлайн-заключение модели — дополнительная редакторская проверка с потенциальными ошибками; ссылки необходимо перепроверять, а код ответа 403 или отсутствие записи в Crossref не свидетельствуют о выдуманной публикации. Офлайн-режим не нуждается в интернете. Отдельные настройки и файлы с секретами в репозиторий не добавлять.

## Развитие

Все достоверные исправления существующих проверок добавляются в единое ядро — обе версии получают их одновременно. Каждый новый маркер сначала относится к справочным, затем проверяется на корпусах известных текстов и лишь после оценки ложных срабатываний может повышаться по значимости. Исходные функции Word-отчёта и вердикта сохраняются.
