# Check-AI: единый интерфейс, два режима, одно автономное ядро

**Адрес пользователя:** https://aminkalinin-boop.github.io/Check-ai/

Пользователь **не вводит URL сервера, API-ключ или код доступа**. На сайте есть только одинаковый переключатель **«Офлайн / Онлайн»**, над загрузкой файла.

## Офлайн

- Все этапы DOCX и текстового анализа, стилометрия, Unicode/HTML, таблицы, ссылки, структура, изображения, заключение Word и подсветка выполняются в браузере.
- Локально в HTML поставляются `vendor/jszip.min.js`, `src/offline_engine.js`, существующие правила, 803 экономических термина (перечень в `src/extra.js`), сигнатуры web UI и характерных конструкций. Нет вызовов внешнего API для анализа.
- `src/offline_engine.js` содержит **реестр 8 этапов, определения 8 групп и 4 уровней, а также 8 сценариев и действия при них**. Вкладка «Метаданные» показывает журнал выполненных этапов. Он не переписывает существующие классификаторы.
- Для использования вообще без соединения с интернетом нужно **однократно скачать** `Check-AI-Offline` в GitHub Actions (распаковать `index.html`) и открыть через браузер с компьютера. Просто закрыть интернет и впервые открыть адрес GitHub Pages не получится, если страница не сохранена браузером: GitHub Pages сам расположен в сети.
- Требование «100% офлайн» понимается как полная автономная доступность **реализованных локальных возможностей**, а не обещание определить 100% ИИ-текстов. Без интернета нельзя обращаться к Crossref или запускать удалённую модель.

## Онлайн

- Выполняет **точно тот же автономный анализ** и показывает все те же вкладки, отчёт и карту. Никакого отдельного интерфейса и ручного запуска дополнений.
- При выборе «Онлайн» пользователь один раз подтверждает информированную отправку **выбранных фрагментов**, не целого файла. Выбор режима не передаёт документ в интернет сам по себе.
- После локального анализа по событию `check-ai:analysis-ready` автоматически выполняются:
  1. Сверка первых пяти библиографических записей через открытый Crossref REST API (если размеченный список обнаружен). Отрицательный ответ не означает галлюцинацию.
  2. Экспертная проверка логики, терминологии, противоречий и ссылок моделью, **если** разработчик подключил защищённый сервер. Запрос включает до 24 ограниченных фрагментов и до 16 библиографических записей. Ответ выводится в существующей вкладке «Признаки», отдельным разделом, и не подменяет локальную шкалу.
- При недоступности сети либо сервера базовый анализ и Word-отчёт сохраняются. В интерфейсе честно указан статус отсутствующей онлайн-экспертизы.
- Кнопки ручного запуска, адресная строка сервера и поле токена **убраны**: пользователю не нужно знать инфраструктуру.

## Подключение модели — действие разработчика, не пользователя

GitHub Pages — статический хостинг: нельзя безопасно разместить там ключ OpenAI API, исполнять Node.js или использовать интерактивную сессию ChatGPT как внешний backend. Нужен **отдельный HTTPS API gateway**, работающий с `online/server.mjs`, а также ключ оплачиваемого OpenAI API.

1. Развернуть Node.js сервис через HTTPS и настроить аутентификацию пользователей **на шлюзе**; не делать публичный анонимный платный API.
2. Шлюз удаляет возможный присланный клиентом `X-CheckAI-Gateway-Secret`, проверяет пользовательскую сессию и сам добавляет этот заголовок со значением серверного `CHECK_AI_GATEWAY_SECRET`. Аналогичный секрет хранится в окружении `online/server.mjs`. Никакого секрета на GitHub Pages.
3. На сервере задать `OPENAI_API_KEY`, модель `OPENAI_MODEL`, `CHECK_AI_GATEWAY_SECRET`, `CHECK_AI_ALLOWED_ORIGIN=https://aminkalinin-boop.github.io`. Допускается альтернативный `CHECK_AI_ACCESS_TOKEN` для тестовых CLI-вызовов, но браузерная версия его не запрашивает.
4. Разработчик прописывает **публичный URL шлюза, не ключ** в `online/site_config.js` как `apiBase`, затем собирает `python3 build.py`.
5. После развёртывания серверной части онлайн-логика запускается без дополнительных пользовательских полей. До развёртывания модель **не подключена**, и выдавать локальный лексический анализ за семантическое мышление нельзя.

## Контрольное качество

Для обеих версий: `python3 build.py`, `python3 tools/build_dual.py`, Node.js 22+ тесты, CI GitHub Actions. Приложение никогда не считает внешнюю подсветку доказательством авторства и не обещает 100% точность обнаружения генераций. Результаты сетевой проверки требуют сверки первичных источников. Оригинальный DOCX не отправляется целиком ни в одном режиме.
