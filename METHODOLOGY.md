# Методика и ограничения Check-AI

## Назначение

Check-AI — локальный инструмент **предварительного аудита документов**, а не детектор авторства. Цель: выявлять технические артефакты переноса контента, лингвистические особенности и недочёты научного документа; предоставлять проверяемые фрагменты специалисту.

Не допускаются автоматические выводы: «текст написал ИИ», «автор написал сам», «X% текста создано ИИ», «автор использовал именно модель Y», «документ гибридный». Количественный охват CSS-разметки не является процентом машинного текста.

## Раздельные блоки доказательств

| Блок | Примеры | Допустимая интерпретация |
| --- | --- | --- |
| Специфичные технические маркеры | Имена классов и стилей чат-интерфейсов, метки переноса | Сходство происхождения оформления; требует подтверждения первичным источником |
| Общие веб-артефакты | HTML, Angular, Tailwind, KaTeX, MathJax | Контент мог проходить через веб-страницу любого назначения |
| Текстовые и статистические особенности | Шаблонные конструкции, лексика, ритм, повторы | Повод для редакторской проверки, не доказательство ИИ |
| Качество научного документа | Ссылки, рисунки, одинаковые числа, терминология | Замечания к научному оформлению, независимо от авторства |

Элементы Word (таблицы, диаграммы, сноски, комментарии, rsid) описывают структуру/историю редактирования, но не подтверждают самостоятельное создание текста. Отсутствие маркеров ничего не доказывает об использовании ИИ. Вывод по одному DOCX всегда ограничен.

## Калибровка и известные ограничения

В репозитории содержатся обезличенные профили 62 статей одного автора 2016–2022 годов и 17 статей 2023–2026 годов. Это **исследовательская пилотная выборка**, а не репрезентативная оценка ложноположительных срабатываний для разных авторов, дисциплин или эпох. Стилометрия запускается только для достаточно длинного преимущественно русскоязычного основного текста (от 600 слов). Значение «сильный» описывает специфичность обнаруженного маркера, не вероятность использования ИИ.

## Протокол последующей валидации

1. Собрать независимый эталон: человеческие документы до широкого распространения генеративных моделей из разных дисциплин, жанров и авторов. Не использовать те же тексты одновременно для выбора порогов и итоговой оценки.
2. Собрать контрольные сценарии с заранее известным происхождением: ручной текст; ручной текст, скопированный из обычной веб-страницы; текст из интерфейса ИИ; вручную вычитанный текст после ИИ; машинный текст, перенесённый без стилей; копирование через Word/LibreOffice/Google Docs; смешанные материалы с таблицами и формулами.
3. Для каждого сценария фиксировать версии ПО, формат, способ копирования и **проверяемую метку происхождения**. Анонимизировать тексты; не добавлять конфиденциальные документы в публичный репозиторий.
4. Считать для каждого маркера матрицу ошибок, FPR, TPR, precision при указанной распространённости классов и 95% доверительные интервалы. Отдельно оценивать обнаружение **веб-переноса** и **генерации текста**.
5. Сверять разметку и локализацию с ручной экспертизой не менее двух независимых проверяющих; разбирать расхождения.
6. Приемочные тесты: корректное открытие DOCX; отсутствие ложных утверждений об авторстве; стабильный экспорт отчёта и подсветки; работа офлайн; проверка на нескольких браузерах.

Для установления способа подготовки текста требуются независимые материалы: оригиналы и черновики, история версий, записи процессов, проверка первичных данных. Результаты нельзя использовать как единственное основание для санкций против автора.
